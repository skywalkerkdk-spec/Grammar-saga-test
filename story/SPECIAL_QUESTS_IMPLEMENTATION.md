# Special quests — prototype implementation

SPECIAL_QUESTS.json contains 18 quests, four bilingual clues and two three-option comprehension tasks each. Existing town IDs and English names follow STORY_DATA v1.1. The interaction_type is a design target, not implemented mechanics. Start with a common evidence board and choice UI; later implement timeline ordering, map selection, matching and other custom interactions without changing evidence or correct answers. Show English first, optional matching colored Korean chunks; ko on clues is a draft gloss, not guaranteed natural Korean. Questions have Korean translations; option translations and full bilingual opening/closing scenes still need editorial work. Preserve existing grammar correction, dungeon unlocks, rewards and saves. Store special quest progress separately by town ID; unlock clues on individual correction or existing dungeon recovery, including legacy clears. Allow retry without penalty, persist collected clues, require all four clues and both correct tasks for special completion. Do not gate existing dungeon access or Grammatica pages on special completion. Reward is a completion flag only; existing souvenir must not be granted twice. Next dialogue is a suggested story link, not a lock; avoid replaying it twice. Implement Passive Lake first, then expand after tests. Verify evidence supports each answer, mobile layout, save migration, repeat visits and optional translation modes. Do not merge or deploy without review.
