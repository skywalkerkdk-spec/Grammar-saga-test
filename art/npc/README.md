# NPC 그래픽 제작 파이프라인 (Chapter II) — 2단계 방식

주민 252명에게 서로 다른 그림을 입힙니다. **그림 생성은 GPT가, 검사·분할·게임 등록은 이 저장소의 도구가** 맡습니다.

## 방식
1. **정면 그림(전원 252명)**: 한 이미지에 24명(6×4), 정면 전신 1컷. 총 **F001~F011 (11장)**. 게임 안에서 128×128로 줄여 쓰며, 대화창에는 같은 인물이 크게 보일 수 있습니다.
2. **걷기 시트(기존 이동형 52명만)**: 정면 그림을 참조해 **4프레임**(왼발·기본·오른발·기본) 걷기 시트 512×512를 한 이미지에 4명씩. 총 **W001~W013 (13장)**. 나머지 주민은 가만히 서 있습니다.
→ GPT 이미지 총 **24장** (처음 계획 71장). 마음에 드는 주민은 나중에 걷기 시트만 추가하면 됩니다.

## 현재 상태
- 제작 목록 `NPC_MANIFEST.json/.csv`(자동 산출: 252명 · 직업 99종 · ID 중복·미배정 0), 요청서 `prompts/`(29개)
- 도구: `tools/npc_sheet_check.py`(검사), `npc_slice_batch.py`(자동 분할·저장), `npc_walk_refs.py`(걷기용 참조 이미지), `npc_build_atlas.py`(게임 등록), `npc_manifest.py`, `npc_batch_prompt.py`
- 게임 연결 완료: `story/maps/npc-atlas.js`, `npc-walk.js`. 등록된 그림이 없으면 기존 그림 그대로 나옵니다.
- **실제 NPC 그림은 아직 등록되지 않았습니다.** (시험 샘플 16명(4×4)은 자동 인식·검사 합격이었으나 정식 배치 요청서로 만든 것이 아니라 등록하지 않았습니다.)

## 규격
| 종류 | 대상 | 규격 |
|---|---|---|
| front | 252명 | GPT 출력: 투명 PNG, 6열×4행 24명, 칸 사이 빈 간격. 도구가 자동으로 잘라 **128×128**(발 y≈122, 가운데)로 저장 |
| walk | 52명 | **512×512 RGBA**, 4열×4행, 칸 128×128. 행: 아래·왼쪽·오른쪽·위(뒷모습). 열: 왼발·기본·오른발·기본(기본=2번째 칸). 발 기준선 y=116 |

## 작업 순서
1. GPT에 `prompts/F001.md`(+ 공통 안내 + 기준 그림)를 보내 정면 배치 이미지를 받습니다.
2. `python3 tools/npc_slice_batch.py F001 받은이미지.png` → 자르고 검사하고 `art/npc/sprites/`에 저장(고해상도 원본은 `art/npc/hires/`). 불합격 주민만 다시 요청합니다.
3. 걷기: `python3 tools/npc_walk_refs.py W001` 로 참조 이미지를 만들어 `prompts/W001.md`와 함께 GPT에 보냅니다. 받은 뒤 `python3 tools/npc_slice_batch.py W001 받은이미지.png`.
4. `python3 tools/npc_build_atlas.py` 로 합격한 것만 게임에 등록합니다.
5. `GRAMMAR_CHROMIUM=<크롬경로> python3 tests/check_npc_walk.py` 와 기존 Chapter II 테스트로 확인합니다.
6. 별도 승인 후 배포(메인 병합은 하지 않았습니다).

## 검사기가 잡는 것
크기·알파·체커보드 배경·빈 칸·칸 경계 잘림·발 기준선 흔들림·프레임별 키 차이·걷는 동작 없음·방향별 옷 색 불일치(경고). **화풍·인물 일관성의 최종 확인은 사람이 해야 합니다.**

## 게임 안 동작
- 걷기 시트가 등록된 주민만 반경 3칸 안에서 걷고, 길목을 막지 않는 칸만 밟습니다. 대화 중이거나 주인공이 옆(대각선 포함)에 있으면 멈춥니다.
- 주인공은 주민 칸을 밟지 못하며, 8방향 옆 칸 어디서든 대화할 수 있습니다.
- 그림이 없거나 불러오지 못하면 기존 정지 그림을 씁니다. 위치는 저장하지 않으므로 저장 데이터에 영향이 없습니다.
